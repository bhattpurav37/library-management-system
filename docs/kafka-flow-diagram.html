Why AFTER_COMMIT? The Kafka send only fires after the DB transaction commits. If the registration fails or rolls back (e.g. ISBN conflict → 409), no event is ever published. The service layer has zero Kafka imports — it only knows Spring's ApplicationEventPublisher.  Failure isolation: if the broker is down, the send fails in the background (whenComplete logs the error) but the API still returns 201 — the book is created.

2  The event on the wire

{ "bookId": 3, "isbn": "9780201616224", "title": "The Pragmatic Programmer", "author": "Andrew Hunt", "occurredAt": "2026-10-29T19:02:13.4528612" } // Kafka message: key = ISBN (string) value = this JSON (no type-info headers)

3  application.yml — every Kafka property and where it is used

PropertyValue (default)Where it is used / what it does
spring.kafka.bootstrap-servers localhost:9092
(env KAFKA_BOOTSTRAP_SERVERS)		 Read by KafkaProducerConfig and KafkaConsumerConfig via env.getProperty(). The broker address both clients connect to. In Docker dev setup this maps to the host listener.
spring.kafka.producer.acks all KafkaProducerConfig — wait for all in-sync replicas to confirm. Strongest durability.
spring.kafka.producer.retries 10 KafkaProducerConfig — producer retries a failed send up to 10 times.
spring.kafka.consumer.group-id library-management-system
(env KAFKA_CONSUMER_GROUP)		 Read by KafkaConsumerConfig. Note: the actual group is book-created because the @KafkaListener(id=...) id overrides it.
spring.kafka.consumer.auto-offset-reset earliest KafkaConsumerConfig — a brand-new group starts reading from the beginning of the topic, so it sees events published before it first connected.
spring.kafka.listener.auto-startup
(application-test.yml only)		 false Test profile only — ITs run without a broker, so the listener container must not start. Set in application-test.yml.
app.kafka.topics.book-created library.book-created.v1
(env KAFKA_TOPIC_BOOK_CREATED)		 Publisher: injected with @Value into BookCreatedEventKafkaPublisher. Consumer: referenced in the @KafkaListener(topics = "${app.kafka.topics.book-created}"). One property wires both sides to the same topic.

4  Who does what (all Kafka classes)

🔧 Config — com.library.config

  • KafkaProducerConfig — builds the typed KafkaTemplate<String, BookCreatedEvent>. JsonSerializer reuses the app's ObjectMapper; type-info headers disabled so consumers don't need our classes.
  • KafkaConsumerConfig — builds the listener container factory. JsonDeserializer fixed to BookCreatedEvent (no headers needed), wrapped in ErrorHandlingDeserializer so one bad message is skipped, not fatal. Ack per record.

📦 Events — com.library.event

  • BookCreatedEvent — Java record: bookId, isbn, title, author, occurredAt. The shared contract on the wire.
  • BookCreatedEventKafkaPublisher — listens for the Spring event AFTER_COMMIT, sends to Kafka keyed by ISBN.
  • BookCreatedEventKafkaConsumer — @KafkaListener that receives and logs each event.

🚀 Producer side — BookServiceImpl

  • Inside the @Transactional register(): after save, calls eventPublisher.publishEvent(new BookCreatedEvent(...))
  • Knows nothing about Kafka — fully decoupled via Spring events.

🧪 Tests — no broker needed

  • Unit: publisher & consumer tested with Mockito mocks.
  • ITs: @MockBean KafkaTemplate (no real send) + listener auto-startup off (test profile).
